# Reuse scoped sessions for external conversations

An external `conversationId` denotes the existing session already scoped to one tenant, user, and knowledge base. The public interface never exposes the Claude session ID; the server retains it to resume model context, while persisted run events and their cursors provide reconnection for an interrupted response. A missing conversation ID creates an External Conversation, but an invalid, cross-knowledge-base, or out-of-scope ID is `404 conversation_not_found` rather than a new conversation. New External Conversations carry a durable origin marker and are excluded from the default workbench session list, while remaining stored for a later dedicated presentation.

For a live remote MCP session, Knowledge Fabric retains the most recent server-issued conversation for each queried Knowledge Base. A later MCP query therefore continues that conversation by default; callers normally omit `conversationId`. A caller may provide a server-issued UUID to select a conversation, or set `newConversation: true` to start a separate one. A request ID is an idempotency key, never a conversation ID. The MCP-session convenience state is not a replacement for the durable External Conversation: after an MCP reconnect, the caller must use the previously returned server-issued UUID to continue it.
