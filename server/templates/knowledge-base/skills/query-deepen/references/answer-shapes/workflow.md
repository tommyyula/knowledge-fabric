# Workflow Answer Shape

Use when the user mainly wants to understand how something progresses over time.

A workflow answer must make the steps explicit. Do not collapse the workflow into vague phases or tell the user to inspect a page for the details.

Cover:
- where it starts and what must already be true
- each meaningful step in order, including who or what acts
- what data, state, ownership, or permission changes at each important step
- where it branches, fails, pauses, retries, or requires human action
- where it ends and what follows from that final state

If the knowledge only supports a partial workflow, explain the known steps and name the missing step-level gap.
